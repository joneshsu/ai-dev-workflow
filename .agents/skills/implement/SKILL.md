---
name: implement
description: 依照 docs/plans/ 中的計畫，以 TDD 方式逐步實作，每個步驟一個 Conventional Commit。在使用者要求實作某份 plan 時使用。
---
請依照使用者指定的計畫檔（位於 `docs/plans/`）實作。使用者可能同時指定要做的步驟編號。

規則：
1. 一次只做一個步驟（若我有指定步驟編號，就只做那一步）。
2. 每個步驟：
   a. 先寫會失敗的測試，執行並確認它失敗。
   b. 撰寫最少量的實作讓測試通過。
   c. 執行完整測試、lint 與型別檢查，全部通過才繼續。
   d. 以 Conventional Commits 格式 commit（例如 `feat(auth): add token refresh`），訊息內容引用 plan 的步驟編號。
   e. 在 plan 檔案中把該步驟勾選為完成。
3. 若要修改的程式碼原本沒有測試，先補上 characterization test（描述目前行為的測試），確認通過後再開始修改。
4. 如果實作過程發現 plan 有問題，**停下來告訴我**，不要自行大幅偏離計畫。
5. 不要修改既有測試來讓測試通過；如果你認為既有測試有誤，先說明理由。
6. 若實際執行的指令（安裝、測試、lint、啟動）與 `AGENTS.md`「常用指令」不一致，或仍標示為「尚未驗證」，在完成步驟後提出更新內容給我確認。M0 Walking Skeleton 全部完成時，也請建議把「目前階段」改為「階段 2：骨架完成」，並提出值得寫入「程式碼慣例」的規則。
7. 每個步驟完成後簡短回報：做了什麼、測試結果、下一步是什麼。
